# 網路連線方案評估

URBAN LIVE 的 Mac 主程式內建伺服器（HTTP + WebSocket，預設埠 8765）。手機必須「連得到 Mac」才能發送彈幕。
以下依實際早會可能遇到的網路情況評估，**第一版預設使用方案 1，不需要任何雲端服務或費用**。

| # | 情境 | 做法 | 手機需要 | 費用 | 適用 |
| --- | --- | --- | --- | --- | --- |
| 1 | **手機與 Mac 在同一個 Wi-Fi**（建議） | 直接掃 QR Code（`http://<Mac IP>:8765/j/<場次碼>`） | 連公司內部 Wi-Fi | 免費 | ✅ 預設方案 |
| 2 | 公司「訪客 Wi-Fi」有用戶端隔離 | 改用內部 Wi-Fi；或請 IT 對會議室網段關閉隔離 | 連內部 Wi-Fi | 免費 | 最常見的連不上原因 |
| 3 | 沒有可用 Wi-Fi，人數少（< 10） | iPhone 個人熱點：Mac 與手機都連同一支 iPhone 的熱點 | 連熱點 | 用該手機的行動數據（流量很小） | 小型會議、臨時備援 |
| 4 | 沒有可用 Wi-Fi，人數多 | 攜帶一台獨立的 Wi-Fi 路由器（不需上網），Mac 與手機都連它 | 連這台路由器 | 一次性硬體 | 固定會議室最穩定 |
| 5 | 手機只有行動網路（4G/5G）、或在不同網路 | 自行用 **Cloudflare Tunnel** 把 Mac 轉成外部網址，在控制面板「外部網址」填入 | 任何網路 | Cloudflare 免費方案 | 需要主持人同意對外開放；第一版**不會自動開啟** |
| 6 | 長期跨地點、遠端參與 | 架設雲端轉送服務（例如 WebSocket 轉送伺服器） | 任何網路 | 需雲端主機 | 第一版不實作 |

## 方案 1：同一個 Wi-Fi（預設）

- QR Code 內容是 Mac 的區域網路 IP，例如 `http://192.168.1.23:8765/j/7KQ2M9XA`。
- 選單列 / 控制面板會顯示目前使用的 IP；Mac 同時有 Wi-Fi 與有線網路時，可在控制面板選擇手機連得到的那一個（通常 Wi-Fi 是 `en0`）。
- 換 Wi-Fi 或 IP 改變時，QR Code 會自動更新。
- AirPlay 鏡像到 Apple TV 也在同一個網路上進行，彈幕流量很小（每則幾百位元組），不會影響鏡像品質。

## 方案 2：訪客 Wi-Fi 用戶端隔離

症狀：手機打開 QR Code 網址一直轉圈或顯示「連不到電腦」，但手機本身可以上網。
原因：訪客網路通常禁止同網段裝置互相連線（AP isolation / client isolation）。
處理：改連內部 Wi-Fi，或請 IT 開放會議室網段；其他方案見 3～5。

## 方案 3：iPhone 個人熱點

1. 主持人的 iPhone 開啟「個人熱點」。
2. Mac 與觀眾手機都連上這個熱點。
3. URBAN LIVE 的 QR Code 會自動使用 Mac 在熱點網段的 IP（通常是 `172.20.10.x`）。

限制：iPhone 熱點同時連線數有限，只適合小型會議。Apple TV 若不在同一個網路，AirPlay 可改用點對點 AirPlay（Apple TV 支援時）。

## 方案 5：Cloudflare Tunnel（進階、選用）

適合「觀眾手機只有行動網路」的情況。**這會讓網際網路上的人也能打開彈幕頁**（仍需要每場不同的隨機場次碼才能發送），請在需要時才使用。

```bash
brew install cloudflared
cloudflared tunnel --url http://localhost:8765
# 會印出一個 https://xxxx.trycloudflare.com 網址
```

把印出的網址貼到「控制面板 → 快捷鍵與進階 → 外部網址」，QR Code 會改用這個網址。關閉 `cloudflared` 後清空該欄位即可回到區域網路模式。

安全設計：
- 透過通道連入時，App 會使用 Cloudflare 提供的觀眾真實 IP 做限流與封鎖（只有來自本機通道的連線才信任這個標頭，區域網路的手機無法偽造）。
- 手機網頁只能「發送彈幕」，沒有任何遠端控制 Mac 的功能。

## 為什麼不預設用雲端

- 規格要求第一版不強制付費雲端、不在未經同意下部署公開服務。
- 區域網路延遲最低（實測回條延遲見 [TESTING.md](TESTING.md)），不受公司對外網路品質影響。
- 訊息不離開會議室網路，簡報與彈幕內容都不會上傳到第三方。
