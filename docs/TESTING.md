# 相容性測試與 Keynote 可行方案

> 原則：**不假設**透明置頂視窗一定能蓋住 Keynote 原生全螢幕簡報。能自動驗證的在 CI 驗證；
> 只能在實機驗證的（Keynote、PowerPoint、AirPlay 到 Apple TV、投影機），App 內建測試工具並提供保底方案。

## 1. 已自動驗證（GitHub Actions，macOS 15）

每次推送程式都會在 GitHub 的 macOS 機器上執行 `scripts/smoke-test.sh`：

| 項目 | 方法 |
| --- | --- |
| 核心邏輯 | `swift test`：HTTP 解析、文字清理、Emoji 字數、限流、軌道分配、視窗層級判斷 |
| 打包 | Apple 晶片 + Intel universal binary、ad-hoc 簽章 |
| 手機 API | 啟動 App 後實際打 HTTP：網頁、狀態、送出（200）、連發限流（429）、錯誤格式（400）、空白（400）、404、405 |
| **彈幕是否蓋在全螢幕視窗上** | `Tools/FullscreenProbe` 做出紅色的滿版測試視窗，截圖後分析像素：紅色 = 測試視窗、藍色膠囊 + 白字 = 彈幕 |

FullscreenProbe 模擬的四種「簡報軟體全螢幕方式」：

| 情境 | 代表 | 預期 |
| --- | --- | --- |
| `fullscreen` 原生全螢幕 Space | YouTube（瀏覽器全螢幕）、PowerPoint / Keynote 編輯畫面全螢幕、預覽程式全螢幕 | 彈幕在上方 |
| `level:1000` 一般 App 以螢幕保護程式層級滿版 | 部分簡報軟體的播放視窗 | 自動層級墊高後，彈幕在上方 |
| `shielding` 一般 App 以 Shielding 層級滿版 | 最極端的置頂視窗 | 自動層級墊高後，彈幕在上方 |
| `capture` `CGDisplayCapture` 擷取螢幕 | 舊版 Keynote 的播放方式 | 參考用（結果寫在紀錄中） |

截圖與報告在每次執行的 Artifacts「smoke-test」中（`report.txt`、`*.png`、`app.log`）。

### 最近一次結果（2026-10-15，GitHub Actions macOS 15，1024×768 虛擬螢幕）

| 情境 | 結果 | 彈幕層級（App 紀錄） |
| --- | --- | --- |
| 原生全螢幕 Space | ✅ 彈幕在上方 | 1000（不需墊高） |
| 層級 1000 滿版視窗 | ✅ 彈幕在上方 | 自動 1000 → 1001 |
| Shielding 層級滿版視窗 | ✅ 彈幕在上方 | 自動 1000 → 2147483629 |
| CGDisplayCapture 擷取螢幕 | ✅ 彈幕在上方 | 自動 1000 → 2147483629 |
| 測試視窗關閉後 | — | 自動回到 1000 |

這證明了 Overlay 的視窗設定與自動層級機制在 macOS 視窗伺服器上確實有效；**但不等於 Keynote 一定沒問題**，因為無法得知 Keynote 播放時實際的做法，仍需第 2 節的實機測試。

## 2. 必須在實機確認（會議前做一次，約 10 分鐘）

CI 機器上沒有 Keynote、沒有 Apple TV，以下項目**只能在你的 Mac 上確認**。App 選單列 →「相容性測試（Keynote / PowerPoint）…」可以協助：

1. 按「開始 60 秒測試」，畫面每 2 秒出現一則「🧪 相容性測試」彈幕。
2. 立刻切到 Keynote 開始播放（或 PowerPoint、PDF、YouTube）。
3. 看 **Mac 螢幕** 與 **Apple TV 投影畫面**，測試彈幕是否出現在簡報上方。
4. 按 Esc 結束播放，回到測試視窗看結果。紀錄檔在 `~/Library/Logs/URBANDanmaku/compat-日期.txt`。

> 測試結果的「✅ / ⚠️」是依視窗層級推算的理論值，**以投影畫面上實際看到為準**。若結果和實際不同，請把紀錄檔傳給開發者，裡面有每秒的視窗層級，可以據此調整。

### 實機測試清單

| # | 情境 | 操作 | 通過標準 |
| --- | --- | --- | --- |
| 1 | AirPlay 鏡像 | 控制中心 → 螢幕鏡像 → 選 Apple TV →「鏡像內建顯示器」 | 相容性測試視窗顯示「啟用中 1 個」；投影機與 Mac 畫面相同 |
| 2 | 一般桌面 | 選單列 → 發送測試彈幕 | Mac 與投影畫面都看到藍色膠囊彈幕；QR Code 在右下角 |
| 3 | 手機連線 | 手機連同一個 Wi-Fi，掃 QR Code，送出文字與 Emoji | 1 秒內出現在畫面上；Emoji 為彩色 |
| 4 | 滑鼠穿透 | 彈幕經過時點擊下方按鈕 / 翻頁 | 點擊正常作用在簡報上 |
| 5 | **Keynote 全螢幕播放** | 相容性測試 → Keynote「播放」 | 測試彈幕出現在投影片上方 |
| 6 | Keynote 視窗播放（保底） | Keynote「播放 > 在視窗中播放」 | 測試彈幕出現在投影片上方 |
| 7 | PowerPoint 投影片放映 | 相容性測試 → 從頭播放 | 測試彈幕出現在投影片上方 |
| 8 | PDF | 預覽程式「顯示方式 > 幻燈片秀」或全螢幕 | 同上 |
| 9 | YouTube | 瀏覽器影片全螢幕 | 同上 |
| 10 | 播放中快捷鍵 | 簡報播放中按 ⌃⌥⌘P / ⌃⌥⌘C / ⌃⌥⌘R | 暫停、清空、QR Code 切換生效，簡報不會跳出 |
| 11 | 切換 Space | 簡報播放中三指滑動切換桌面再切回來 | 彈幕持續顯示 |
| 12 | 解析度變化 | 開始 / 停止 AirPlay 鏡像 | 彈幕自動填滿新解析度，QR Code 仍在角落 |

## 3. Keynote 可行方案（依序嘗試）

### 方案 A：直接全螢幕播放（預設，先測這個）
App 預設「自動」層級：若 Keynote 播放視窗用比彈幕高的層級蓋滿螢幕，會自動把彈幕墊到它上面一層。用相容性測試確認。

### 方案 B：改用「最高層級」
設定 → 進階 → 視窗層級 →「最高層級」（Shielding 之上），再跑一次相容性測試。適用於簡報軟體擷取整個螢幕的情況。

### 方案 C：Keynote 允許其他 App 使用螢幕
部分 Keynote 版本在「Keynote > 設定（偏好設定）> 幻燈片秀」有「允許 Mission Control、Dashboard 和其他 App 使用螢幕」之類的選項。若你的版本有，請勾選後再測。（各版本名稱與是否存在不一定，以實際畫面為準。）

### 方案 D（保底，一定可行）：視窗模式播放
Keynote「播放 > 在視窗中播放」（舊版名稱為「在視窗中播放幻燈片秀」）。視窗化的幻燈片只是一般視窗，彈幕必定在它上方。為了讓投影畫面接近全螢幕：

1. 系統設定 → 桌面與 Dock → 開啟「自動隱藏和顯示 Dock」，並把「自動隱藏和顯示選單列」設為「永遠」。
2. 按住 Option 點幻燈片視窗左上角綠色按鈕（或拖曳視窗邊緣）把視窗放大到填滿螢幕。**不要**直接點綠色按鈕進入全螢幕。
3. 簡報者附註會在另一個視窗，可移到旁邊或關閉。

### PowerPoint、PDF、YouTube
- **PowerPoint**：預設「投影片放映」先用相容性測試確認；保底為「投影片放映 > 設定放映方式 >『觀眾自行瀏覽（視窗）』」。
- **PDF**：預覽程式全螢幕為原生全螢幕 Space（CI 已驗證此類情境）；Adobe Acrobat 的「全螢幕模式」請用相容性測試確認。
- **YouTube**：瀏覽器全螢幕為原生全螢幕 Space（CI 已驗證此類情境）。

## 4. 在本機重跑自動測試

```bash
./scripts/build-app.sh
./scripts/smoke-test.sh   # 會暫時改動 com.urban.danmaku 的設定並在結束時清除
```

第一次執行截圖時 macOS 可能要求終端機的「螢幕錄製」權限；沒有權限時截圖類測試會顯示「⚪️ 無法判斷」，API 測試不受影響。
